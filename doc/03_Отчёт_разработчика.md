## 3. Принятые технические решения

| Решение | Причина |
| --- | --- |
| Замеры и обмен вынесены в отдельные подсистемы ОП и RMQ; связь с ТО — через переопределяемые модули | зависимости односторонние, ОП и RMQ можно перенести в другую конфигурацию без изменений |
| Расчёт плана вынесен в чистые функции `ТО_Планирование` | логику можно проверить модульными тестами без данных в базе; один расчёт используют и задание, и форма плана |
| Событие складу записывается в outbox в транзакции наряда, отправляется фоновым заданием | недоступный брокер не мешает проведению, а откат наряда откатывает и событие |
| Входящее сообщение подтверждается брокеру только после записи в базу; дубли отсекаются по message-id и eventId | сообщения не теряются, а повторная доставка не создаёт вторую заявку |
| Запись замеров и сообщений — в привилегированном режиме с восстановлением исходного режима (`ВключитьПривилегированныйРежим = Не ПривилегированныйРежим()`) или через привилегированный общий модуль | роли ТО не нужны права на объекты ОП и RMQ; внешний привилегированный режим не сбрасывается |
| Пароль брокера хранится в отдельном регистре `RMQ_ПаролиПодключений`, форма показывает заглушку | пароль не читается из справочника, формы или отчётов |
| Клиентский замер проведения наряда и учёта наработки (`ПередЗаписью` → `ПослеЗаписи`) | в замер попадает время, которое видит пользователь |
| Замер записывается и при ошибке операции (формирование, рассылка, создание заявки) | сбойные прогоны не выпадают из статистики APDEX |
| Измерение `Идентификатор` в регистре замеров | два замера в одну секунду не затирают друг друга |
| Тесты размещены в расширении YAxUnit | тестовый код не попадает в поставку конфигурации |
| Печатные формы — на макетах документов и общем серверном модуле, без БСП | в конфигурации нет БСП; подключение её подсистемы печати ради четырёх форм несоразмерно |
| Форма движений строится по метаданным документа | одна форма на все документы; новые регистры подхватываются без доработки формы; видна история статусов складской заявки из независимого регистра |
| Печатная форма наряда берёт материалы из того же расчёта, что и складская заявка | бумажный наряд и заявка складу не расходятся |

## 4. Соответствие стандартам разработки

| Требование | Как выполнено |
| --- | --- |
| Стандарт 658: не использовать «ИЛИ» в условиях запроса | отбор по ТС подставляется вместо маркера процедурой `УстановитьУсловиеОтбораПоТС`: либо `Поле В (&ТСОтбор)`, либо `ИСТИНА` |
| Стандарт 655: срез последних с отбором — через временные таблицы | срезы строятся в `ВТ_Показания`, `ВТ_Пробеги`, `ВТ_Наработка` |
| Запросы не выполняются в цикле | данные для расчёта плана и рассылки собираются одним пакетом запросов |
| Привилегированный режим включается только там, где нужен, и корректно восстанавливается | запись замера восстанавливает исходный режим; операции RMQ, которым нужны полные права, собраны в привилегированном модуле `RMQ_ОбменПолныеПрава` |
| Корректность данных справочников | ключевая операция не записывается с T ≤ 0 и с неуникальным именем; подписка не записывается с неизвестным обработчиком или второй активной подпиской на очередь |
| Стандарт 469: имена общих модулей | суффикс «Сервер» стандарт допускает, но не требует. Имена `ТО_Сервер` и `RMQ_ОбменСервер` оставлены без изменений, чтобы не менять вызовы в коде и тестах |
| Префиксы объектов доработки | все объекты начинаются с `ТО_`, `ОП_` или `RMQ_` |

## 6. Ограничения

- PinkRabbitMQ работает только на сервере и только на Windows x86/x64 и Linux x64.
- Доставка событий — «хотя бы один раз»: система склада тоже должна отбрасывать повторы по `eventId`. Задержка доставки — до 60 с плюс время отправки пакета.
- Событие создаётся только при первом проведении наряда; изменения материалов после этого на склад не передаются.
- Без регулярных показаний дата ТО не прогнозируется, точка плана оценивается только по порогу счётчика. Показания из систем мониторинга транспорта автоматически не загружаются.
- Замеряются шесть операций; новая операция добавляется в коде.
- Регистр замеров и справочники сообщений автоматически не очищаются.
