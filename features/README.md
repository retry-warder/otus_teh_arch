# Каталог features

Сценарии поведения Vanessa Automation на Gherkin, по подсистеме «ТО».

> **Стенд 10.11.2026:** регресс 20 из 20, демо-сценарий с RabbitMQ 1 из 1, видео с озвучкой 1 из 1. Платформа 8.3.27.2130, Vanessa 1.2.043.42, файловая база.
>
> **Перед прогоном** в базе не должно быть других автомобилей с флажком «Планировать ТО», например тестового парка из обработки «Заполнение тестового парка». Регламентное формирование и форма «План ТО» формируют наряды по всему парку, и проверки «создано 1» и «у А123ВС77 ровно 1 наряд» упадут.

## Запуск

Все пути в `tools/JSON/va-config*.json` заданы от корня репозитория, поэтому рабочий каталог Vanessa (`workspaceRoot`) — корень репозитория.

1. Эталонная база: конфигурация из `src/cf`, пользователи `Администратор` (полные права) и `ТестЧтение` (без роли «ТО», только чтение) — для сценария с тегом `@права`. Регламентные задания выключены. SMTP не настраивать: рассылка проверяется по записанному письму.
2. В `tools/JSON/va-config.json` в `КлиентыТестирования` указать путь к базе (`ПутьКИнфобазе`), порты и пользователей.
3. Собрать библиотеку шагов: `src/epf/ТО_Шаги.xml` → `build/epf/ТО_Шаги.epf` (команда — в `src/epf/README.md`).
4. Запустить менеджер тестирования:

```
1cv8c.exe ENTERPRISE /F "<база>" /N Администратор /TestManager /Execute "<путь>\vanessa-automation-single.epf" /C "StartFeaturePlayer;VAParams=<репозиторий>\tools\JSON\va-config.json;QuietInstallVanessaExt;workspaceRoot=<репозиторий>"
```

Отчёты allure и junit, лог и скриншоты пишутся в `build/reports`, итог (0 — успех) — в `build/reports/BuildStatus.log`. В репозиторий они не попадают.

## Что стоит знать

- Сценарии используют реальные имена элементов форм (`ФактДатаТО`, `ФормаПровестиИЗакрыть`, `СформироватьНаряды`, `ОстаткиНормативТО`…). При переименовании элементов сценарии нужно править.
- Даты в сценариях фиксированные (ноябрь 2026). Расчёт идёт по шагу «дата расчёта», а не по системному времени, поэтому прогон воспроизводим в любой день. Исключение — команды из форм (список автомобилей, «План ТО»): они берут текущую дату, и показания в сценариях даны так, чтобы машина уже была в окне.
- Шаг `Дано тестовые данные ТО очищены` физически удаляет данные прошлых прогонов вместе с движениями документов, висячие записи регистров ТО и историю статусов удалённых заявок. Исходящие и входящие сообщения RMQ он не трогает.
- Демо-сценарий требует рабочего RabbitMQ: подключение по умолчанию, топология `to.events` → `sklad.zayavki`, подписка с обработчиком «ТО.СкладскаяЗаявка», включённый обмен. Константа `ОП_ОтключитьЗамеры` выключена.
- Автозапись видео (`video/`) работает только на Windows в тонком клиенте с VanessaExt; нужны ffmpeg и ImageMagick 7 в PATH, Balabolka (`balcon.exe`) и русский голос Windows. Ролик появляется в `build/reports/video`.
