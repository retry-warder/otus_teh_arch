# Формирование нарядов на ТО (расчёт материалов)

Курсовой проект курса «Архитектор 1С».

Тема реализована в демо-конфигурации 1С:Предприятие 8.3 как подсистема «Техническое обслуживание автотранспорта» (ТО). Подсистема сама формирует наряды по плану ТО, считает потребность в материалах и передаёт её складу через RabbitMQ. Инфраструктура вынесена в подсистемы «Оценка производительности» (ОП, замеры и APDEX) и «Обмен RabbitMQ» (RMQ).

## Что реализовано

Сквозной процесс: диспетчер вводит показания одометра → план ТО считает, сколько осталось до каждого вида ТО → регламентное задание в 06:00 формирует наряды → при первом проведении наряда в outbox записывается событие `naryad.created` → событие уходит в обмен `to.events` и попадает в очередь `sklad.zayavki` → обработчик создаёт складскую заявку → кладовщик её исполняет → мастер закрывает наряд, следующее ТО считается от факта. Каждая ключевая операция попадает в замеры APDEX.

**Расчёт материалов.** Нормы расхода заданы в справочнике видов ТО: материал, содержание и количество на одно ТО. Потребность собирается по всем видам ТО наряда (`ТО_СкладскиеЗаявки.ДанныеЗаявкиПоНаряду`): одна строка на пару «вид ТО + позиция», повторы суммируются, позицию без номенклатуры задаёт текст содержания. Дата потребности — плановая дата ТО по среднесуточной выработке; если её нельзя посчитать, дата наряда плюс 7 дней, но не раньше текущей даты. Подробно — `doc/01_Технический_проект.md`, раздел 4.5.

**Отчётность и печать.** Отчёт «Проведённые ТО» показывает закрытые ТО за период по автомобилям: план и факт наработки, отклонение, виды ТО. У наряда, складской заявки, учёта наработки и ввода остатков есть печатные формы (кнопка «Печать») и команда «Движения документа» — записи всех регистров по документу, включая историю статусов складской заявки. Эта часть покрыта тестами YAxUnit (`ОМ_ТО_Печать`). Подробно — `doc/01_Технический_проект.md`, раздел 4.6.

## Ограничения

- Доставка событий «хотя бы один раз»: система склада тоже должна отбрасывать повторы по `eventId`.
- Событие создаётся только при первом проведении наряда; изменения материалов после этого на склад не уходят.
- PinkRabbitMQ работает только на сервере, на Windows x86/x64 и Linux x64.
