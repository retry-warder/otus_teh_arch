# Каталог tests

Тесты кодом на движке YAxUnit. Сами модули тестов лежат в расширении `src/cfe/YAXUNIT/CommonModules`: YAxUnit запускает тесты из расширения, поэтому отдельной копии здесь нет.

## Модули

| Модуль | Что проверяет |
| --- | --- |
| `ОМ_ТО_Планирование` | порядок ТО по нормативам: окно оповещения, единичные виды, раннее закрытие, первое ТО |
| `ОМ_ТО_Сервер` | расчёт плана нарядов по базе и создание нарядов по плану |
| `ОМ_ТО_РасчетМатериалов` | потребность в материалах по наряду и дата потребности |
| `ОМ_ТО_СкладскиеЗаявки` | приём данных складской заявки, повторный вызов, проверки позиций, статусы |
| `ОМ_ТО_Интеграция` | событие `naryad.created` в outbox при проведении наряда и создание заявки по входящему событию |
| `ОМ_ТО_Печать` | отчёт «Проведённые ТО», печатные формы, движения документа |
| `Док_ТО_Наряды_МО`, `Док_ТО_УчетНаработки_МО`, `Док_ТО_ВводОстатков_МО` | проведение документов ТО |
| `ОМ_ОП_ОценкаПроизводительности`, `Спр_ОП_КлючевыеОперации_МО` | замеры и APDEX, справочник ключевых операций |
| `ОМ_RMQ_Обмен`, `Спр_RMQ_ПодпискиНаОчереди_МО` | регистрация исходящих сообщений RabbitMQ, подписки на очереди |

Модули с суффиксом `_Данные` создают тестовые данные конструктором YAxUnit. Каждый тест работает на своих данных в транзакции и после прогона ничего в базе не оставляет.

## Запуск

1. Загрузить расширение из `src/cfe/YAXUNIT`, снять «Безопасный режим» и «Защита от опасных действий».
2. Запустить клиент с параметром `RunUnitTests`:

```
1cv8c.exe ENTERPRISE /F "<база>" /N Администратор /C "RunUnitTests=<репозиторий>\tools\JSON\yaxunit.json"
```

Отчёт junit и `exit-code.txt` пишутся в `build/reports/yaxunit` (путь задан в `tools/JSON/yaxunit.json`, при другом расположении репозитория его нужно поправить). В репозиторий отчёт не попадает.
